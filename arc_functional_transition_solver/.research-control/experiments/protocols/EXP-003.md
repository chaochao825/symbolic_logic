## Primary question

unchanged anchor-abstention-then-disagreement policy recover complementary
visual hypotheses under a fixed 30% activation budget?

2. Compile and audit the recursive dataset without a solution file.
3. Run and freeze the recursive candidate pool and native cost receipt.
4. Construct the exact sorted 100-task universe from the seal and freeze

6. Freeze the heterogeneous population.  A population authorization must bind

   controls.  Do not train a controller.

## Gates

### G-002a: candidate complement

The visual provider must contribute at least 3/100 strict task-level exclusive
hits over the recursive anchor.  Also report union increment, query-level
composition, abstentions, exact output overlap, and all neither-hit tasks.

Failure of G-002a parks `C-001` and makes the recruitment result descriptive
only; it is not permission to change providers or thresholds on this cohort.

### G-002b: functional recruitment

At the predeclared 30-task prefix:

- recover at least two marginal-value tasks;
- recover at least half of all anchor-miss/union-hit tasks;
- strictly exceed the upper median of the 256 frozen random task-count orders;
- consume no more than 35% of full visual-provider native GPU seconds.

Report the 10%, 20%, 30%, and 50% curves.  Also compare against deterministic
random orders truncated by the same observed GPU-second budget as the fixed
policy; this native-cost control is secondary because runtimes are known only
after execution.

Passing both gates partially supports `C-002` and permits work on final pass@2
selection (`C-003`).  It does not permit a learned router yet.

## Invalidity conditions

- Any reserve query output is opened before both candidate freezes,
  population, and recruitment plan pass content-identity checks.
- The plan reads a visual candidate, provider score, query solution, or
  task-level marginal-value label.
- Dataset audit is not clean or any provider consumes query gold.
- Shared query input identities differ, task universes drift, or A/B replay
  differs.
- Provider source/checkpoint/configuration differs from the contract above.
- An unrelated process is displaced from a GPU.

## Resource cap and stop rule

- One reference-scale NVARC run on one idle A800.
- One full VARC run totaling at most 100 tasks, each with the existing 2,400 s
  timeout; safe independent shards may run on idle GPUs but each task retains
  exactly the single-GPU reference semantics.
- No model pretraining, controller training, provider tuning, or post-outcome
  feature changes.
- Stop immediately on an invalidity condition, failed provider receipt, or
  G-002a complement failure after oracle opening.

## Outcome mapping

- Confirmatory positive: G-002a and G-002b both pass.
- Mechanism null: complement passes but G-002b fails.
- Provider null: G-002a fails.
- Boundary: result is valid but the earlier demo-only exposure or native-cost
  comparison limits the strength of inference.
- Invalid: any leakage, identity, replay, source, or execution condition fails.
