- Status: frozen
- Date: 2026-08-12
- Gate: G-000
- Claim: C-000
- Candidate line: L-000
- Lane: integrate/post-hoc audit

## Question

Do the already frozen NVARC/TRM and VARC artifacts reproduce their exposed
strict complement under a provider-independent content-addressed envelope,
without allowing solutions into construction?

## Preconditions

- Use only the existing confirmatory candidate freezes and native cost receipts.
- The ARC-TGI cohort and solution file identities must match the anchor records.
- Freeze the population before opening the solution file in a separate command.
- Treat 92/89/95 as exposed expected values; this audit can validate evidence
  plumbing but cannot newly confirm `C-000`.

## Evidence status and independence

- Evidence tier: post-hoc audit of independently frozen development evidence.
- Independent statistical or verification unit: strict whole ARC-TGI task;
  query-level counts are secondary diagnostics.
- Frozen boundary: candidate freezes and run receipts precede solution scoring;
  no provider is rerun.
- Preprocessing/model-selection boundary: none; exact output identity only.
- Outcome-exposure rule: task rows stay external and the repository stores a
  compact summary committing to the full result ID.

## Fairness and leakage guards

- Both providers must cover identical task/query input identities.
- Provider internals and native rankings remain unchanged; no common reranker.
- Solutions are forbidden to the freeze command and population schema.
- Required checks: provider-freeze canonical validation, content-hash replay,
  forged-population rejection, homogeneous-family rejection, and byte-identical
  A/B output.

## Method

Merge all raw/top-10 candidates from the recursive and visual freezes.  Deduplicate
identical grids per task/query under an identity that excludes provider name,
while preserving every provider contributor.  After freeze, score strict
provider coverage, provider-exclusive coverage, union coverage, pairwise
contingency, and cross-provider per-query composition.

## Acceptance threshold

Both replays must return recursive strict coverage 92/100, visual strict
coverage 89/100, union 95/100, recursive-exclusive 6/100,
visual-exclusive 3/100, and identical population/result/summary identities.

## Falsifier

Any query/input mismatch, query-gold field in the freeze, non-deterministic
identity, invalid upstream freeze, or metric disagreement with the independent
base-union artifact invalidates the audit and blocks the recruitment gate.

## Outcome mapping

- Support: evidence normalization is valid; open a separate recruitment gate.
- Oppose: not applicable to the scientific claim because outcomes are exposed.
- Inconclusive: identities validate but independent metrics disagree.
- Boundary: complement exists only through cross-provider per-query composition.
- Invalid or engineering failure: any leakage, identity, schema, or replay guard fails.

## Resource cap and stop rule

CPU-only, 30 minutes, two deterministic replays, zero provider training or GPU
jobs. Stop on protocol invalidation or after the A/B identity comparison.

## Failure interpretation

- Invalid: the protocol cannot support a scientific conclusion.
- Engineering failure: execution failed before valid evidence existed.
- Null: a valid run did not meet the effect threshold.
- Adverse: a valid run moved in the harmful direction.
- Boundary: the claim holds only in a narrower region.
- Contradictory: valid evidence conflicts with an accepted claim or prior evidence.

## Required outputs

Write a result record from `results/RESULT-TEMPLATE.md`, update `experiments/registry.csv`, and preserve all valid outcomes.
