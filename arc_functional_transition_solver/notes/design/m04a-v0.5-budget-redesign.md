# M04a v0.5 budget redesign

Status: successor protocol decision after the preserved v0.4 diagnostic failure.
This note does not authorize reuse or retry of any v0.1--v0.4 run identity.

## Preserved observation

The one-shot v0.4 diagnostic run
`m04a-preflight-20260712-04` completed 100 maximum-context optimizer updates,
the fixed 8-lane/12-step inference probe, and the diagnostic checkpoint
roundtrip. It then failed closed with `BUDGET_EXCEEDED`. The preserved
content-addressed checkpoint is diagnostic-only and is neither selectable nor
training evidence.

The frozen v0.4 projection was

```text
H + G + P + F
+ 50,000 * ceil(T100 / 100)
+ (25 * 2,656) * ceil(T100 / 1,600)
+ 25 * R + S + 300 seconds.
```

`T100` is the sum of the 100 measured maximum-context update wall times; `H`,
`G`, `P`, `F`, `R`, and `S` are the lock handshake, handshake-to-preflight gap,
complete preflight endpoint, fresh reconstruction, checkpoint roundtrip, and
selection probes. Even if every other positive term were ignored, v0.4 could
pass only when `T100` was at most about 158.71 seconds. The checkpoint time
gives only a conservative approximately 345.75-second upper envelope for the
completed probe; the exact timing ledger was not persisted and must not be
reconstructed from file modification times.

## v0.5 scientific protocol

The successor protocol freezes:

```text
optimizer updates       20,000
gradient accumulation   16 (8 ARC2 + 8 ReARC episodes per update)
training episodes       320,000 (160,000 per source)
warmup                   2,000 updates
cosine decay             updates 2,001--20,000, ending at zero
validation interval      2,000 updates
validation passes        10
validation rows/pass     2,656, unchanged
sampler                   64 lanes, 12 denoising steps, unchanged
```

This preserves the effective batch, source balance, masked-generation model,
literal validation rows, and large-candidate sampler. It reduces exposure by
60 percent, so conclusions must be reported as a fixed-budget
source-complementarity experiment, not as the capability limit of a fully
trained 50k model.

Reducing gradient accumulation was rejected because it changes effective
batch size, gradient noise, update grouping, and optimizer trajectory. Reducing
sampler lanes or denoising steps was rejected because pool inference is outside
the 24 GPU-hour training cap and those changes would directly weaken the
large-candidate hypothesis.

## Timing-region correction

The v0.4 preflight reused one pre-tokenized CPU batch. Production update timing
starts before episode construction and also includes augmentation, mask audit,
CPU tokenization, tensor creation, and host-to-device transfer. A successor
projection therefore cannot claim an end-to-end bound while timing only the
pre-tokenized GPU path.

The v0.5 maximum-context fixture must construct all 16 synthetic episodes and
their audit rows inside every measured update, then use the production episode
preparation and CUDA update functions. Every synthetic episode has ten 30x30
demonstrations, a 30x30 query/target, and all 900 target cells masked. The outer
wall timer starts before construction; the CUDA event timer remains around the
GPU phase.

On the local frozen production data and mmap indices, a read-only 100-update
CPU census measured about 36.43 ms/update for real episode construction,
auditing, and CPU preparation. The proposed all-maximum synthetic path measured
about 167.49 ms/update on the same host, approximately 4.6 times the observed
production mean. These measurements guide fixture design only; the target-237
one-shot preflight remains the authoritative budget gate.

## Failure evidence correction

Every terminal diagnostic outcome must be replayable. A complete
`BUDGET_EXCEEDED` failure publishes a closed-world `preflight-failure/` bundle
containing the canonical failure report, exact 100-row ledger, training and
inference summaries, overhead report, launch/runtime/lock bindings, and a
commitment to the diagnostic checkpoint. The bundle is explicitly ineligible
for training evidence, its checkpoint is unselectable, and the same run identity
cannot be retried. The command still exits nonzero and never publishes a
`preflight-gate/` on failure.

Early OOM or incomplete-projection failures use a strict schema branch that
permits only the evidence available before their terminal point.

Exact-preflight owns the diagnostic commit-last boundary. The cost probe's measured
write interval closes on the durable hidden staging payload and returns a prepared
owner without exposing a final name. Verified loading, fresh reconstruction,
selection, report/snapshot validation, outer RNG restoration/cleanup, budget
projection, construction and validation of the complete `PreflightFailure` or
`PreflightResult`, and the final lock check must all succeed before exact-preflight
performs the no-replace rename. The rename is covered by the fixed five-minute
margin, while the independently published evidence bundle is the durable authority.
Projection/report/final-lock/rename errors before the commit are published through
the strict `PROJECTION_INCOMPLETE` partial branch with diagnostic-write count zero.
Failure manifests record that lock release was attempted and that process exit is
the final backstop; they do not claim an unsuccessful close already released the lock.

## Campaign hard stop

Passing a projection is necessary but not sufficient. Before any training
launch, the same-lock campaign coordinator must check cumulative lock-held wall
time at every optimizer-update, validation-episode, checkpoint-publication, and
final-selection boundary. Exactly 24 GPU-hours is accepted; 24 GPU-hours plus
one nanosecond is rejected. A stopped or partial checkpoint is never selectable,
and the budget is checked again immediately before selected-checkpoint
publication.

## Identity consequences

The update horizon changes the training configuration, learning-rate closure,
checkpoint-selection closure, schema configuration, short replay fixture,
runtime/test fingerprints, launch plan, input bundle, deployment, run ID, and
attempt nonce. The model architecture, parameter count, split/shards, literal
validation manifest, sampler semantics, and Python runtime lock may be reused
only by byte/hash commitment. No v0.4 mutable directory or identity is reused.
