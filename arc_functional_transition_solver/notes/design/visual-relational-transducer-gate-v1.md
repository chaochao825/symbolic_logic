# Visual relational transducer gate v1 — frozen 2026-08-11

## Development evidence used to choose the family

The collision-free 49-task development intersection has the following frozen
raw/top-10 exact overlap:

- VARC raw oracle: 44/49;
- NVARC top-10 oracle: 45/49;
- union: 46/49;
- VARC only: 1;
- NVARC only: 2;
- neither: 3.

The three union failures admit the same representation-level description but
not the same concrete rule: a cell correspondence followed by either a global
palette homomorphism or a row/column aggregate color function. This motivates
one typed family rather than three task-ID relations.

No further operator may be added after this protocol is frozen.

## Frozen representation family

Each program is the Cartesian product of exactly two typed nodes:

1. `coordinate`: one of the eight D4 transforms;
2. `color`: one of:
   - a demonstration-induced global color homomorphism;
   - foreground count in the transformed row plus one learned integer offset;
   - foreground count in the transformed column plus one learned integer offset.

The family therefore contains exactly 24 structural hypotheses. Colors,
offsets, and mappings are inferred from demonstrations only. A hypothesis is
selectable only when it executes exactly on every demonstration. Query output,
VARC samples, NVARC candidates, task IDs, and generator witnesses cannot alter
the inferred program.

The program family is intentionally same-canvas. It cannot claim canvas repair,
object insertion/deletion, arbitrary affine motion, cropping, composition, or a
new handwritten spatial relation.

## Query-blind visual certificate and allocation

For each query, compute the fraction of frozen VARC posterior samples that:

- have the query-input canvas shape; and
- preserve the number of non-modal-background cells.

The task certificate score is ordered by:

1. minimum foreground-count-preserving posterior fraction across its queries,
   descending;
2. total unique VARC plus NVARC candidates, descending;
3. exact output overlap between the two frozen pools, ascending;
4. task ID, ascending.

The visual arm allocates the new family to the first `ceil(0.30 * N)` tasks.
The 30% allocation and ordering above are frozen before implementation.

## Equal-native-cost controls

The cold arm selects the same number of tasks with the pre-existing seed
`visual-trace-repair-cold-v1-20260809`, ordered by SHA-256 of
`seed + NUL + task_id`. On every selected task both arms reserve exactly:

- 24 program hypotheses;
- 24 times the number of demonstrations in program executions;
- 24 times the number of queries in query executions, with deterministic
  padding when a structural hypothesis is inapplicable.

The static-family audit runs the family on every task only to separate candidate
language coverage from visual allocation. It is not an equal-cost primary arm.

Every emitted output must be:

- generated by a typed serialized program;
- demonstration exact;
- a valid ARC grid;
- content-novel relative to the frozen VARC and NVARC candidate union.

An action with zero novel candidates must report `frontier_changed = false`.

## Gates

Development is diagnostic and already outcome-exposed. It may establish that
the grammar executes as intended but cannot validate the research claim.

The frozen 100-task confirmation gate is:

- at least 5 strict tasks recovered outside the frozen NVARC/VARC union;
- visual allocation recovers more strict tasks than the equal-cost cold arm;
- all recovery candidates are demo-exact and novel;
- clearing the visual certificate changes the allocated task set;
- no task-level confirmatory outcome or solution is opened before the family,
  allocation rule, cold seed, candidates, and native-cost ledger are frozen.

Failure of this gate blocks controller training and triggers a reformulation of
the dynamic functional-switching claim.
